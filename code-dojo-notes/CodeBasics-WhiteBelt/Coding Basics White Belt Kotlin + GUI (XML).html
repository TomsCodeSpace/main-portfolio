Key Concepts

Variables and Constants

1. What is a variable?

A variable is a container that stores information that can change while the program runs.

2. When should I use a variable?

Use a variable whenever you expect the value to change later.

3. Why should I use a variable?

Variables let your app remember information like scores, names, or health.

4. What is a constant?

A constant stores information that should never change after it is created.

5. When should I use a constant?

Use a constant for values like your app name, tax rate, or company name.

6. Why use a constant instead of a variable?

It prevents accidental changes and makes your code safer.

7. What does var mean?

var creates a variable that can change.

8. What does val mean?

val creates a constant that cannot change.

9. When should I choose var?

Choose var when the value needs to be updated.

10. When should I choose val?

Choose val whenever possible because it makes your code more reliable.

Data Types

11. What is a data type?

A data type tells Kotlin what kind of information is being stored.

12. What is an Int?

An Int stores whole numbers like 5, 10, or 200.

13. When should I use an Int?

Use it for counting, scores, ages, and quantities.

14. What is a Double?

A Double stores decimal numbers.

15. When should I use a Double?

Use it for money, measurements, and averages.

16. What is a String?

A String stores text.

17. When should I use a String?

Use it for names, addresses, messages, and sentences.

18. What is a Boolean?

A Boolean stores only two values:

  • true
  • false

19. When should I use a Boolean?

Use it whenever something is either yes/no or on/off.

20. Why are data types important?

They help Kotlin understand how to work with your data correctly.

Input

21. What is input?

Input is information the user gives your app.

22. What is an EditText?

An EditText is a textbox where users type information.

23. When should I use an EditText?

Whenever you want the user to enter text or numbers.

24. Why do I use .text.toString()?

Because EditText stores editable text, and you usually need a normal String.

25. What happens if the user types nothing?

The String will simply be empty.

26. Why do I convert text into numbers?

Because math only works on numbers, not text.

27. What does .toInt() do?

It converts text into an integer.

28. What does .toDouble() do?

It converts text into a decimal number.

29. When should I read input?

Usually after the user presses a button.

30. Why shouldn't I read input before the user types?

Because there won't be anything to read yet.

Output

31. What is output?

Output is information your app displays to the user.

32. What is a TextView?

A TextView displays text on the screen.

33. When should I use a TextView?

Whenever you want to show information.

34. Why use a TextView instead of an EditText?

TextView is for displaying information, not typing it.

35. What is a Toast?

A Toast is a small popup message.

36. When should I use a Toast?

For quick messages like "Saved!" or "Deleted!"

37. Why should I display results?

Users need feedback to know what happened.

38. What does .text = do?

It changes what the TextView displays.

39. When should I update a TextView?

After something changes.

40. Why is output important?

Without output, users can't see what your app is doing.

Basic Math

41. Why do programs perform math?

To calculate answers automatically.

42. What does + do?

Adds numbers.

43. What does do?

Subtracts numbers.

44. What does do?

Multiplies numbers.

45. What does / do?

Divides numbers.

46. What does % do?

Finds the remainder after division.

47. When is % useful?

When checking if numbers are even or odd.

48. What does ++ do?

Adds one to a variable.

49. What does - do?

Subtracts one from a variable.

50. Why is math important in programming?

Many programs need calculations for games, finance, science, and everyday apps.

Conditionals

51. What is an if statement?

It lets your program make decisions.

52. When should I use an if statement?

Whenever different situations need different actions.

53. What is an else statement?

It runs if the if statement is false.

54. Why use if/else?

It allows your app to react differently based on information.

55. What does == mean?

Checks if two values are equal.

56. What does > mean?

Checks if one value is greater than another.

57. What does < mean?

Checks if one value is less than another.

58. Why are conditionals important?

Without them, every program would always do the exact same thing.

Random Numbers

59. What are random numbers?

Numbers chosen unpredictably by the computer.

60. When should I use random numbers?

Use them for dice rolls, card games, enemy behavior, loot drops, quizzes, and guessing games.

These five projects introduce an important architectural pattern that differs from your CLI programs:

                 ([ APP START ])
                       ↓
              [ LOAD XML LAYOUT ]
                       ↓
              [ CONNECT UI VIEWS ]
                       ↓
                  ⏸ WAIT
                       ↓
                [ USER ACTION ]
                       ↓
                [ EVENT FIRES ]
                       ↓
               [/ GET INPUT /]
                       ↓

                       ↓
              { DECISION? }
                ↙       ↘
              YES       NO
               ↓         ↓

                ↘       ↙
                   ↓
              [/ OUTPUT /]
                   ↓
                  ⏸
                WAIT
                   ↓

The big conceptual difference

Your earlier CLI programs generally followed:

START
 ↓
INPUT
 ↓
PROCESS
 ↓
OUTPUT
 ↓
END

Kotlin Android introduces:

START
 ↓
SETUP UI
 ↓
WAIT
 ↓
EVENT
 ↓
INPUT
 ↓
PROCESS
 ↓
OUTPUT
 ↓
WAIT
 ↓
EVENT
 ↓
...

That's the beginning of event-driven programming.

        }
    }

Project 5 - Pass or Fail Checker

Step 1

Create:

  • EditText
  • Button
  • TextView

Step 2

Read the user's grade.

Step 3

Compare it to 70.

Step 4

Display Pass or Fail.

class MainActivity : AppCompatActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)

        val editGrade = findViewById<EditText>(R.id.editGrade)
        val buttonCheck = findViewById<Button>(R.id.buttonCheck)
        val textResult = findViewById<TextView>(R.id.textResult)

        buttonCheck.setOnClickListener {

            // Step 2
            val grade = editGrade.text.toString().toInt()

            // Step 3
            if (grade >= 70) {

                // Step 4
                textResult.text = "Pass"

            } else {

                // Step 4
                textResult.text = "Fail"
            }
        }
    }
}
